# HENSENG Super App — Phase 5: Chrome extension and store readiness

## Chrome extension

`pnpm --filter @henseng/app build:extension` builds a Manifest V3 extension from the same app code. It produces `dist-extension/` (load unpacked) and `dist-extension.zip` (Chrome Web Store).

**How it works**

- Clicking the toolbar icon opens HENSENG in Chrome's side panel.
- Keys live only in that panel's memory, so closing it locks the wallet. The encrypted vault is kept in the extension's own storage, which websites can't reach.
- Permissions: `sidePanel` only, with no access to websites.
- The security policy allows the extension's own scripts plus WebAssembly (needed for XMTP encryption). No remote code is loaded.

**What the build does**

1. Exports the web app.
2. Copies XMTP's WebAssembly file next to the code.
3. Renames everything starting with "_", which Chrome refuses (Expo names its folder `_expo`), and rewrites every reference.
4. Adds the manifest, the service worker, the boot script and the icons.
5. Checks the result and zips it. The build fails if Chrome would reject anything.

**Tested in Chrome (12/12):**

- The extension loads, and the toolbar icon opens the side panel.
- Its permissions are minimal.
- The app runs inside the extension, and sign-in to the API works.
- XMTP's encryption engine runs under the extension's security policy; it fails only at the network, which is blocked in the sandbox.
- Balances and swap quotes work.
- Reopening locks the wallet, and unlocking works.
- There are no security-policy or script errors.

## App Store and Google Play readiness

- **iOS privacy manifest:** the required-reason APIs React Native uses, and no tracking.
- **Android:**
  - backups are off, so the encrypted vault never leaves the device through cloud backup;
  - unneeded permissions are blocked (microphone, overlay, storage, media);
  - the final permissions are camera, internet and vibrate.

  Both were confirmed by generating the native projects.
- **`eas.json`:** a submit profile (Android internal track, as a draft).
- **Native projects** (`android/`, `ios/`) are generated by EAS and are git-ignored.

## Account deletion (required by Apple and Google)

**In the app:** Profile → Danger zone → **Delete HENSENG account**. It needs your password and "DELETE" typed out.

**What it deletes:** the profile, community memberships and messages, notifications, devices, and reports you sent.

**Communities you own:** they pass to their most senior remaining member, or are deleted if you're the only one in them.

**What it leaves alone:** the wallet and funds, which live on the device and the blockchain.

**Endpoint:** `DELETE /api/v1/me`. Admin accounts are refused. It's tested in the API suite and in the browser.

## Privacy policy

`/privacy` on the web app describes what the code actually does: what stays on the device, what the server stores, which services receive what, the camera, how long data is kept, and deletion.

The operator name and contact come from `NEXT_PUBLIC_LEGAL_ENTITY` and `NEXT_PUBLIC_PRIVACY_EMAIL`. Until both are set, the page shows a warning.
